- L2: **E4S1 shipped — provider plugin ABI v1 + directory loader (WP-1501, PR `feat/wp-1501-provider-plugin-abi`)** — implemented per the PO-approved sketch, no shape changes. **ABI** (`docs/provider-plugin-abi.md`): cdylib, entry `pi_provider_plugin_init() -> *const PiProviderVtable` (NULL = not a plugin), vtable = `abi_version()` (core checks `== 1`, mismatch → typed log line + skip), `name()`, `list_models()` (registry-shaped camelCase entries; the vtable name is authoritative for `provider`), `stream_open(req_json) -> {"handle"|"error"}`, `stream_next(handle) -> event JSON | NULL` (events `delta` / `done` (with the `AssistantTurn` JSON) / `error`; exactly one terminal event), `stream_close(handle)` (idempotent), `auth_start(req_json)`/`auth_status(req_json) -> {"state": "pending"|"done"|"failed", ...}` (`done.credential` is stored by the core via `auth::save_credential` — plugins never touch `auth.json`), `dispose()`. All cross-boundary strings are NUL-terminated UTF-8; single error convention `{"error": "..."}`; string ownership = valid until the next vtable call on the same thread (the core copies immediately). **Loader** (`src/provider/plugin.rs`): at startup, `<exe dir>/providers/` (bundled) then `<agentDir>/providers/` (user); platform exts `.so/.dylib/.dll`; name collision → user dir wins, override logged; every failure (dlopen, missing symbol, NULL vtable, `abi_version` mismatch, bad `list_models` JSON, panic — `catch_unwind` per ADR 0006) is a typed log line, run continues. **Registry/dispatch**: plugin models merge into the registry (bundled catalog + `models.json` + plugins, the v0 per-id limit unchanged); `--provider`/`--model` resolve plugin providers before builtins; new `ProviderDriver::Plugin` seam — the vtable is driven from a `spawn_blocking` task (deltas cross an mpsc channel; the async executor is never parked); the plugin provider is core-owned (the sidecar bridge is never involved). **Login UX** (`auth login <plugin> [--api-key] [--no-browser]`): core-driven poll loop (500 ms / 15 min), prints the sign-in URL, stores the returned credential; `--api-key` prompts for a key and stores `{"type":"api_key",...}`. **Sample** (`plugin-samples/openai-compat/`, crate `pi-sample-compat`): reference ABI v1 implementation + the e2e fixture; provider `sample-compat`, OpenAI-compat SSE streaming via `reqwest` (0.13, async, rustls), mock loopback login, model list via `PI_SAMPLE_VARIANT` (bundled/user). **Build isolation**: the sample is a STANDALONE crate (own `[workspace]` — first attempt used `default-members`, which turned out to flip pre-existing pi-ext clippy lints on in CI's clippy mode; standalone keeps the CI commands byte-identical to main). Normal `cargo build`/`cargo test`/`cargo clippy` never compile it; the e2e builds it on demand (`cargo build --manifest-path`), so CI's `cargo test` on all three OSes covers it. **Dependencies**: `libloading = "0.9"` (latest stable 0.9.1; API change vs 0.8: `Library::new` and `lib.get` are `unsafe` now — used under the ABI SAFETY comments); the sample's `reqwest`/`tokio`/`futures-util`/`serde_json` match the root crate's existing versions (no new root deps). **TDD evidence**: RED — with the loader finding no plugins (bundled dir emptied; binary otherwise identical): `pi-rust auth login sample-compat --no-browser` → `"pi-rust auth login <provider>" requires an interactive terminal` (plugin path absent) and `--provider sample-compat --model bundled-model` → `fatal: provider sample-compat is not a built-in or models.json provider, and the sidecar is unavailable` — the four acceptance behaviors are absent. During implementation the e2e failed RED repeatedly against partial builds (e.g. `the plugin stream ended without a done event`).
