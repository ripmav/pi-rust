- L2: **E4S1 shipped — provider plugin ABI v1 + directory loader (WP-1501, PR `feat/wp-1501-provider-plugin-abi`)** — implemented per the PO-approved sketch, no shape changes. **ABI** (`docs/provider-plugin-abi.md`): cdylib, entry `pi_provider_plugin_init() -> *const PiProviderVtable` (NULL = not a plugin), vtable = `abi_version()` (core checks `== 1`, mismatch → typed log line + skip), `name()`, `list_models()` (registry-shaped camelCase entries; the vtable name is authoritative for `provider`), `stream_open(req_json) -> {"handle"|"error"}`, `stream_next(handle) -> event JSON | NULL` (events `delta` / `done` (with the `AssistantTurn` JSON) / `error`; exactly one terminal event), `stream_close(handle)` (idempotent), `auth_start(req_json)`/`auth_status(req_json) -> {"state": "pending"|"done"|"failed", ...}` (`done.credential` is stored by the core via `auth::save_credential` — plugins never touch `auth.json`), `dispose()`. Normal `cargo build`/`cargo test`/`cargo clippy` never compile it; the e2e builds it on demand (`cargo build --manifest-path`), so CI's `cargo test` on all three OSes covers it. **Dependencies**: `libloading = "0.9"` (latest stable 0.9.1; API change vs 0.8: `Library::new` and `lib.get` are `unsafe` now — used under the ABI SAFETY comments); the sample's `reqwest`/`tokio`/`futures-util`/`serde_json` match the root crate's existing versions (no new root deps). **TDD evidence**: RED — with the loader finding no plugins (bundled dir emptied; binary otherwise identical): `pi-rust auth login sample-compat --no-browser` → `"pi-rust auth login <provider>" requires an interactive terminal` (plugin path absent) and `--provider sample-compat --model bundled-model` → `fatal: provider sample-compat is not a built-in or models.json provider, and the sidecar is unavailable` — the four acceptance behaviors are absent.
