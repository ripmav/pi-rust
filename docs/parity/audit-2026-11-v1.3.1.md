**Top-10 most user-impactful gaps** (ranked by what an original-pi user would notice first):

1. **System prompt is a one-line placeholder; no context-file discovery** — base prompt is `You are pi-rust, a minimal Rust core for the extension-bridge PoC. Use the provided tools.` (`$R/src/agent.rs:14`); nothing reads `AGENTS.md`/`CLAUDE.md`/`.pi/SYSTEM.md`; no upstream `<tools>`/`<rules>` prompt sections. Extensions can replace it via `before_agent_start`, but out of the box every run differs from pi. (Unchanged since the stale audit.)
2. **Thinking levels have no provider-side effect** — `/thinking`, RPC `set_thinking_level` (absent), extension `setThinkingLevel`, and `thinking_level_change` session entries all work, but **no driver sends thinking/reasoning parameters** (no `reasoning_effort`, no anthropic `thinking`, no `thinkingLevelMap`/`thinkingFormat`/budgets/`samplingParams` handling). Evidence: no thinking-related fields in `$R/src/provider/{openai,anthropic,google,bedrock}.rs`; `ModelRaw.thinking_level_map: None` for all models.json models (`$R/src/models_json.rs:159`); E4S2 known limitation "v0 stream request carries no temperature/reasoning/toolChoice/session" (`$R/docs/epics.md` E4S2).
3. **No provider compat system at all** — the upstream `compat` machinery (~30 flags: cache control, session affinity, prompt-cache key/retention, mid-convo system messages, strict tools, grammar tools, thinking formats, finish-reason inference, …), retry policy, and cache warming have no counterpart. Consequence: the same wire behaves less correctly on proxy/compat endpoints, no prompt caching, naive retry (429/5xx single retry). Evidence: none in `$R/src/provider/*.rs`; upstream `docs/models-configuration.md` §Compatibility, `docs/settings.md` (retry.*, cacheWarming).
4. **RPC mode implements 1 of 33 upstream commands** — only `prompt` (with `streamingBehavior: steer|followUp` queued as follow-up runs, a documented deviation); all 32 others answer `Unknown command` (`$R/src/cli.rs:1570-1610`). No `get_state`, `set_model`, `compact`, `bash`, `fork`, `get_entries`, `get_tree`, `export_html`, …
5. **Built-in tools: 4 of 8, and no tool selection** — `bash/read/write/edit` only; no `grep`, `find`, `ls`, `powershell` (`$R/src/tools.rs:15-23`); no `--tools`/`--exclude-tools`/`--no-builtin-tools`/`--no-tools` flags; the `defaultTools` setting is parsed but **inert** (only `config.rs`, never consumed).
6. **In-session session management and session output absent** — no `/tree` navigation, `/new`, `/fork`, `/clone`, `/name`, `/import`, double-Esc; no `/export`, `/share`, `/bug`, `--export`, `export_html`, `get_session_stats` (no stats at all). Files are still upstream v3 trees, but the UI/RPC cannot navigate or output them. Evidence: `$R/src/tui/mod.rs:299-460` (dispatch; rest "not supported in v0"); no export/share code in `$R/src/`.
7. **24 of 43 bundled catalog providers are unreachable** — no core driver, no plugin, not in the OpenAI-compat family table: `ant-ling, baseten, fireworks, minimax, minimax-cn, mistral, moonshotai, moonshotai-cn, nvidia, opencode, opencode-go, openai-codex, qwen-token-plan(×4), typesafe, vercel-ai-gateway, xiaomi(×4), zai, zai-coding-cn` → typed error at provider build (`$R/src/provider/mod.rs:774-796` + fall-through `unknown provider`). (Improved from the stale audit's 14/43: see #24 below.)
8. **No package management, no self-update** — `pi install/remove/uninstall/list/update/config`, npm/git/local package sources, `--extension` one-shot packages, `PI_SELF_UPDATE_COMMAND`, version checks: none. Only subcommand is `auth login` (`$R/docs/cli-reference.md`).
9. **MCP: no OAuth, no resource tools, no management UI/CLI** — the core hosts stdio + streamable-HTTP servers natively (tools/list, tools/call, upstream naming/schemas, `exposure`+`toolExposure`, `${ENV}` expansion, `registerMcpServer` forwarding, `mcp_servers_change`), but `oauth`/`auth` servers are skipped (D17), there are no `list_mcp_resources`/`list_mcp_resource_templates`/`read_mcp_resource` tools, no `/mcp` TUI manager, no `pi mcp add/remove/list/login/logout` CLI, no `mcp.log`. Evidence: `$R/src/mcp.rs` (methods: initialize/tools-list/tools-call/tools_list_changed only); `$R/docs/bridge-protocol.md` §MCP servers "Out of scope (core v0)"; upstream `docs/mcp.md`.
10. **TUI advanced terminal features absent** — no mouse/selection/scroll-wheel, no inline image display (kitty/iterm2), no OSC 52 clipboard, no OSC 8 hyperlinks, no truecolor control, no external editor (`$VISUAL`/`$EDITOR`), no file autocomplete, no working indicator, no fullscreen options, no copy-on-select, no `/settings` menu, no `/reload`. Evidence: no `Mouse`/`OSC52`/`kitty`/`hyperlink` matches in `$R/src/tui/`; `/copy`, `/settings`, `/reload` "not supported in v0".

Also notable: **classifier and image models are unreachable** (codemode hosted with `models: false`, `modelRegistry` is a stub — upstream's `models.classify()`/`models.generateImages()` surfaces, incl. via `ctx.modelRegistry`, do not exist in pi-rust).

**Headline.** pi-rust v1.3.1 is a functional core-loop port with a now-substantial native provider/MCP/oauth layer (M13–M15 closed the models.json, core-MCP and oauth gaps from the stale audit), upstream-format session files, unmodified-TS extension compatibility via a Node sidecar (bridge protocol v6), project trust, skills/templates, auto-compaction, and a working (if feature-thin) TUI. The biggest user-visible losses are in *model behavior fidelity* (placeholder system prompt, no thinking effects, no compat/caching), *control surfaces* (RPC commands, CLI flags, slash commands, settings fields), *session lifecycle* (tree/export/stats), and *ecosystem* (packages, self-update, MCP OAuth/resources, classifier/image models).

**models.json / OpenAI-compatible custom endpoints — PARTIAL (was MISSING).**

Fields implemented (provider): `baseUrl`, `api`, `apiKey`, `models[]` (provider `name` not parsed). Model: `id, name, reasoning, input, cost{input,output,cacheRead,cacheWrite}, contextWindow, maxTokens` (upstream defaults 128000/16384 applied). `apiKey` resolution: literal, `$ENV_VAR`/`${ENV_VAR}` with `$$`/`$!` escapes (upstream `resolveConfigValue` template subset), unset var = typed error naming the var; `!command` = typed rejection (D12 — no shell from config files); then auth.json store, then ambient env.

**Provider driver coverage — 19 of 43 (was 14).**
Mechanisms:
- *Native core drivers (15):* `anthropic` (messages SSE + tools + images), `google` (generateContent SSE), `google-vertex` (generateContent, **API-key auth only** — ADC/bearer typed rejection), `azure` (chat/completions + api-version + deployment map — upstream also serves OpenAI models on the **Responses** API; pi-rust is completions-only), `amazon-bedrock` (converse-stream, manual SigV4, **env credentials only** — `AWS_PROFILE` typed rejection, no ECS/IRSA), `kimi-coding` (openai-completions + core oauth), and the OpenAI-completions family `openai, groq, cerebras, deepseek, together, huggingface, openrouter` (`$R/src/provider/mod.rs:774-784`).

**Extensions (TS).** The sidecar runs the **unmodified** pin's `discoverAndLoadExtensions` + `ExtensionRunner`; discovery order = upstream (project `.pi/extensions` (trust-gated), agent dir, `--extension-dir`); validated unmodified examples: hello, with-deps (npm deps), permission-gate, claude-rules, plan-mode, prompt-customizer + sidecar-crash degradation path. Event catalog + decision semantics per `docs/bridge-protocol.md` (message catalog). Not delivered (extensions load, handlers never fire or are no-ops): `project_trust`, `resources_discover`, `before_provider_request/headers`, `after_provider_response`, `provider_stream_event`, `session_before_switch/fork/tree`, `ui_prompt_start/end`, `tool_execution_*`, `agent_settled`; `turn_end`/`message_end` delivered without mutation results; TUI renderers (message/entry/tool renderers, markdown transformers) accepted-ignored; `setLabel` no-op; virtual models accepted-ignored; `!command` in extension `apiKey` rejected; no per-turn `AbortSignal`. The full `ctx.ui` beyond the dialog subset + custom-pane descriptor (widgets, footer/header, autocomplete, editor readback, `onTerminalInput`) is no-op/identity (headless-safe, upstream noOp semantics).

**pi-ext (Rust extension platform).** `pi-ext/` crate (ADR 0003) with complete bridge-v6 wire types (`pi-ext/src/wire/`) and API core (WP-1201–1204 per roadmap); per `docs/epics.md` E1S2–E1S5 are **open**: no in-process core-extension loading, no user Rust-extension runtime, no ported core extensions shipped, no scaffolding. ADRs 0001/0002/0004/0005/0006 specify the accepted design (subprocess user peers over bridge, full 1:1 API mirror, shared discovery/trust, six bridge-matrix ports as bundled core extensions, in-process `.so` loading). So today: TS extensions only; the Rust platform is design + types + API crate, not a runtime.

**Security.** Project trust per #41 (parity, documented D1–D8 deviations). No sandboxing of tools (same as upstream default; upstream docs cover Docker Sandboxes/OpenShell — no pi-rust counterpart). Agent dir created 0700, auth.json 0600-on-create, key material redacted from logs/errors (typed errors name env vars, never values).

**Configuration/state.** Agent dir resolution = upstream (`--agent-dir` > `PI_CODING_AGENT_DIR` > `~/.pi/agent`); reads `settings.json` (5 effective fields), `auth.json`, `models.json`, `sessions/`, `prompts/`, `keybindings.json`, `themes/`, `trust.json`; project `.pi/` (settings + mcp.json + skills + prompts + extensions) only for trusted projects. `--isolated` = fresh temp agent dir (hermetic tests).

**Release/CI.** release-please → tag → 5-target release (x86_64-linux-gnu, aarch64-linux-musl, x86_64/arm64 macos, x86_64 windows msvc) + `install.sh` (node ≥ 22.19 required — the sidecar); tarball ships the built `upstream/` tree (no npm install); `catalog-verify` CI guard; perf baseline gate (`benches/baseline.json`); PTY TUI tests Linux/macOS only (Windows = manual smoke checklist).

3. `git log -1` confirmed HEAD `5e0cb5af…` before starting; no files modified in either repo; no GitHub calls.
4. Upstream version-skew assessed between the pin (64a15f4, ≈v1.5.x) and v1.6.0 from the v1.6.0 changelog.

**Limits (could not verify without running pi-rust / live services).**
- pi-rust binary was not executed: TUI rendering/interaction, exit-code behavior, provider streaming against real endpoints, and the e2e claims (sidecar-degraded runs, plugin logins, MCP over real servers) are taken from the code + test sources, not re-run.

- Extension-event delivery gaps are taken from the bridge-protocol "Out of scope" list plus a spot-check of the sidecar's event handling; every individual extension example was not executed.

- The pinned upstream tree at `$R/upstream/` (64a15f4) was used for pin-era semantics; v1.6.0-vs-pin diffs beyond the changelog were not line-diffed.
