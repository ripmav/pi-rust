# Bundled model catalog (frozen)

Committed snapshot of the upstream provider catalog — the **single source of
truth** for pi-rust's bundled model registry. `build.rs` merges
`catalog/data/*.json` into the `models.json` blob compiled into the binary.

**D14 (PO, 2026-11-24, Option 3):** the catalog is frozen for pi-rust —
deterministic builds, no live models.dev, no dependence on the local upstream
tree (its `packages/ai/src/providers/data/` is regenerated from the live
models.dev API on every `npm run build`). The CI `refresh-catalog` step is
gone; the `catalog-verify` composite action only detects stale restored
build caches (content fingerprint, see `.github/actions/catalog-verify/`).

## Byte stability

`build.rs` reads files in readdir order but merges into serde_json maps
without `preserve_order` (BTreeMap-backed): every object is emitted with
sorted keys, so the same input files always produce the same bytes.

## Re-pin procedure (refresh the snapshot when new models are actually needed)

Run from the repo root, with the pinned upstream already cloned and built
(README "From source", step 1). `npm run build` hits the live models.dev API
on purpose — that is the one allowed live fetch:

```sh
# To pick up a NEWER catalog, first bump UPSTREAM_SHA in
# .github/workflows/ci.yml and the README pin, then re-clone upstream at
# that commit (README "From source", step 1).
cd upstream
npm ci && npm run build        # regenerates packages/ai/src/providers/data/
cd ..
cp upstream/packages/ai/src/providers/data/*.json catalog/data/
git diff --stat catalog/data   # review what the refresh changed
cargo build                    # build.rs re-merges; the <1000-entry guard panics on a truncated copy
```

Commit the `catalog/data/` delta (+ any pin bump). CI's `catalog-verify`
guard then guarantees no runner keeps a stale baked catalog (stale restored
rust-cache outputs are dropped and rebuilt by content fingerprint).
